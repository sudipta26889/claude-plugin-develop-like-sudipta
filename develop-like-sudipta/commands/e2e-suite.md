Generate the project-wide end-to-end test suite by stitching every per-phase test markdown and spec into one umbrella.

**You MUST invoke the `sd-claude-code-access` skill first** — specifically `references/browser_testing.md` (end-of-run E2E suite section) and `references/playwright_generation.md` (umbrella spec pattern).

## Inputs

- `$1` — workspace path (required)

## Procedure

1. **Resolve test root** — default `$1/docs/e2e-testing/`, override via env `BROWSER_TEST_ROOT`.
2. **Discover per-phase tests** — list all `phase-*.md` files in the test root, sort by phase number. Skip files that don't match `phase-<digits>-<slug>.md`.
3. **Build coverage table:**
   ```markdown
   | Phase | Feature | Last status | Last run |
   |-------|---------|-------------|----------|
   | 1     | login   | pass        | 2026-05-11 09:14 |
   | 2     | dashboard | pass      | 2026-05-11 10:02 |
   | 3     | checkout | fail       | 2026-05-11 11:30 |
   ```
   Read each per-phase md's `## Result` section + filename mtime.
4. **Stitch the narrative** — write `$1/docs/e2e-testing/E2E-SUITE.md`:
   - Header with coverage table above.
   - Per-phase section: Test ID, Objective, link to the per-phase md, one-line summary of the steps, current status.
   - Closing section: any phases skipped + why, any phases red + their latest fix attempt, the next thing the user should run.
5. **Emit umbrella spec** — write `$1/docs/e2e-testing/specs/e2e.spec.ts`:
   ```typescript
   // source: docs/e2e-testing/E2E-SUITE.md
   // generated by sd-claude-code-access /e2e-suite
   import './phase-1.spec';
   import './phase-2.spec';
   // ... one per existing per-phase spec
   ```
   Skip imports for phases whose per-phase spec doesn't exist (yet).
6. **Scaffold once if absent:** `specs/fixtures.ts`, `specs/playwright.config.ts`, `docs/e2e-testing/RUNNING.md` (the only file documenting how to run the suite — every other file describes the tests themselves).
7. **Report to the user:**
   - Coverage summary (X green / Y red / Z skipped)
   - Path to `E2E-SUITE.md`
   - Path to `e2e.spec.ts`
   - One-line command to run the suite: `npx playwright test --config=docs/e2e-testing/specs/playwright.config.ts e2e.spec.ts`
8. **Emit CI workflow** — invoke `scripts/emit_ci_workflow.sh <workspace>`. Writes `.github/workflows/e2e.yml` adapted to the project's package manager (npm/pnpm/yarn), detected Node version (`engines.node` or default 20), dev-server URL (env `DEV_SERVER_URL` > `.cc/config.json` > `http://localhost:5173`), and Playwright config path. Idempotent — the file's first line is `# source-hash: <hash>`; a re-run with the same inputs prints `unchanged` and leaves the file untouched. Safe to re-run after every `/e2e-suite`.

## Don't

- Don't fabricate phase results. If a phase has no markdown, it's "not run" — say so in the coverage table.
- Don't include phases marked `pass-with-warnings` as green without flagging them.
- Don't overwrite per-phase mds. This command only writes the umbrella files.
- Don't generate snapshot tests. The umbrella stays simple — just imports + a coverage doc.
- Don't commit a hand-edited `e2e.yml` that doesn't match the source-hash — it will be regenerated next `/e2e-suite` run.

# v5.0.x stability hardening — 2026-05-12

> **Mode:** A (greenfield phased) — driving CC against the plugin's own repo.
> **Budget:** 8 hours wall-clock.
> **Goal:** Identify concrete stability problems in v5.0.1 and ship fixes. Bug-driven TDD throughout.
> **Driver:** Cowork (manager) + cc-orchestrator (L2, every minute) + cc-coordinator-keepalive (L3, every 5 min).

## Why now

v5.0.1 just shipped (BUG-2 closed). Pre-flight survey of `~/.cache/ccbridge/learnings/` + `distillation/last-7days.md` showed sparse cross-project signal, but a static-grep sweep over the plugin source surfaced four concrete drift candidates the loop has not yet caught:

1. **`CLAUDE.md:13`** — declares `version (currently 4.4.0)`. Actual is `5.0.1`. Six minor versions + one patch of unreviewed prose drift.
2. **`develop-like-sudipta/README.md`** — versioning section jumps from `v4.0.0` directly to `v5.0.0`. Missing entries for v4.1 → v4.8 (~25 changelog deltas), and no v5.0.1 entry at all.
3. **`cc-coordinator-keepalive` has NO eval.** Landed in v5.0.0 as part of the L3 architecture; the only adjacent test is `test_cc_orchestrator_idle_exit.sh` (L2 idle path only). The keepalive's stall-detection logic, done-check, and self-disable contract are completely untested.
4. **No shellcheck integration.** 25 bridge scripts ship with `bash -n` syntax checks but no semantic linting. v4.2-C did one manual bash 3.2 sweep, but new scripts (`sync_learnings.sh`, `propose_fix_pr.sh`, `dispatch_signature.sh`, `escalate.sh`) have never been audited.

The plan addresses each, lands fixes via bug-driven TDD (failing test first, every time), and closes with a v5.0.2 release if any code changes shipped.

## Phase breakdown (6 phases, ~1h each)

### Phase 1 — Doc drift: CLAUDE.md + README.md catch-up

**Files:**
- `CLAUDE.md` — fix the stale version claim. Replace `(currently 4.4.0)` with `(currently 5.0.1; bump on every release)`. Also audit the rest of CLAUDE.md against current repo state — referenced file paths, version-specific notes.
- `develop-like-sudipta/README.md` — backfill versioning entries v4.1 → v4.8.0 (one-line each, sourced from `plugin.json` description), then add the v5.0.1 entry. Format consistent with existing v5.0.0 + v4.0.0 entries.

**Verify-gate:** `bash -n` on no scripts changed (none expected); `git diff --check` for whitespace; `python3 -c 'json.load(open("plugin.json"))'` still parses.

**Commits (2):**
- `docs(claude-md): refresh version + repo-layout claims for v5.0.1`
- `docs(readme): backfill v4.1—v4.8 + v5.0.1 changelog entries`

### Phase 2 — cc-coordinator-keepalive eval

**File:** `develop-like-sudipta/skills/sd-claude-code-access/evals/test_cc_coordinator_keepalive_idle.sh`

Write the eval for the L3 watchdog's idle-exit path: when no `active-job.json` exists across all workspaces, the keepalive must Step-1 early-exit with `[keepalive] idle: no active jobs` and not invoke any MCP. Mock the `find` step + assert exit message.

Then write `test_cc_coordinator_keepalive_stall_detection.sh`: set up a fake workspace with a stale `orchestrator-heartbeat` (>7 min old), assert keepalive writes `<ws>/.cc/escalations/keepalive-<ts>.md` and emits `keepalive_stall` state event.

**Bug-driven TDD:** if either eval reveals a bug in the keepalive SKILL.md prompt or the supporting bridge scripts, write the failing test FIRST, then fix, then four greens.

**Commits (2-3):**
- `test(keepalive): RED — idle-exit when no active jobs`
- `test(keepalive): RED — stall detection writes escalation file`
- (optional) `fix(keepalive|escalate|state): … per bug-driven TDD`

### Phase 3 — cc-orchestrator active-job eval

**File:** `develop-like-sudipta/skills/sd-claude-code-access/evals/test_cc_orchestrator_active_job.sh`

The existing `test_cc_orchestrator_idle_exit.sh` covers Step-1 quota-saver only. Extend coverage: fixture an `active-job.json` + a mock `state.json` showing a `phase_complete` event, assert the orchestrator would write the `phase-<N+1>.md` trigger via `send.sh` (mock send). Bug-driven TDD if anything misbehaves.

**Commit:** `test(orchestrator): RED — phase advance on phase_complete event`

### Phase 4 — shellcheck wiring (best-effort, conditional)

**Probe first:** `command -v shellcheck`. If absent: skip Phase 4 entirely and proceed to Phase 5 (no install — that's the user's call).

If present: add `evals/test_shellcheck_clean.sh` that runs `shellcheck -S error` across `scripts/*.sh` + `hooks/scripts/*.sh` and asserts exit 0. Fix any errors via bug-driven TDD (each error → red test → fix → green).

**Commit (if shellcheck present):** `test(scripts): shellcheck error-level clean across bridge scripts`

### Phase 5 — script-eval coverage matrix

**File:** `develop-like-sudipta/skills/sd-claude-code-access/evals/test_script_eval_coverage.sh`

Enforce: every `scripts/*.sh` (excluding read-only diagnostics like `read.sh`/`keys.sh`) must have at least one `evals/test_*.sh` that references it. Generate a matrix; fail if coverage drops below threshold (≥80% of scripts have at least one eval mention).

Bug-driven TDD: for any script without an eval, write a minimal smoke eval (does it exit 0 with `--help` or expected no-op input?).

**Commits (variable, one per script that lacked an eval).**

### Phase 6 — release v5.0.2

If Phases 1-5 produced any commits:

1. Bump `plugin.json` version `5.0.1` → `5.0.2`.
2. Prepend a v5.0.2 narrative to the description (paragraph summarizing what hardened).
3. Run the full eval sweep — all evals green.
4. `git tag -a v5.0.2 -m "..."` (manager handles tag + push + repackage outside CC's scope).

If Phases 1-5 produced zero commits (all evals passed pre-existing code): document the dry run in `docs/plans/v5.0.x-stability-hardening-2026-05-12.md` itself with a `## Result` section, and skip the version bump.

**Commit:** `release(v5.0.2): stability hardening — keepalive eval, orchestrator coverage, …`
